# 个人数据导出 `/export_my_data`

此命令是通用机器人功能，不依赖第二种 TG 框架、外部文件存储或新的数据库字段。

## 使用

在机器人**私聊**中发送 `/export_my_data`，收到 `telegram-my-data.json`。文件包含该账户的 Telegram ID、当前存储的基本资料、语言设置、数据时间戳和本页的反馈正文及时间戳，格式为 JSON UTF-8。

每页最多 50 条反馈；如还有旧反馈，机器人会在随后的消息及文件 `pagination.nextCursor` 中给出下一页的完整命令 `/export_my_data <cursor>`。继续运行此命令可分批下载历史记录，直到提示完成。无反馈时仍会导出账户基本资料。

## 权限和保密

- 必须由 Telegram 私聊中本人发起；用户身份由收到的 Telegram `from.id` 确认，不接受在参数里指定用户 ID。
- 服务器首先查询该 Telegram ID 对应的账户，然后使用其**内部 `userId`** 限定每一页查询。游标只决定从何处翻页，**不赋予任何访问其他用户数据的权限**。
- 游标做长度、版本、时间戳和 ID 校验；无效输入会要求从第一页重新开始。
- 只把数据文件发回用户私聊，不写入应用日志、数据库中的新表或对象存储。Telegram 客户端以及聊天另一端的存储/转发受 Telegram 平台机制影响；下载后请妥善保管，勿公开分享。

## 边界

- 多页导出**不是同一事务内的时间点快照**；如果有人在导出期间新增、删除或修改数据，分页结果可能与随后数据库状态不同。
- 机器人只导出**本项目持久存储的数据**，不代表 Telegram 平台保存的聊天记录或其他应用的数据。
- 每次最多上传一个小文件，避免单次 Webhook 长时间扫描大量个人数据；Telegram API 超时/网络重试可能导致文件被重复发送，但不会改变数据库记录。
- 导出命令与删除确认按钮不受应用层限流阻断，以避免隐私操作无法完成；仍应避免短时间内重复请求。
- 如需删除项目内持久数据，私聊使用 `/delete_my_data`，然后在 5 分钟内点击签名确认按钮；先导出再删除。如管理员通知在删除之前已发送给外部 Telegram 聊天，应用无法撤回平台侧已有副本。
